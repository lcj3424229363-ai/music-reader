## 4 helper API

```js
// 1. 反向转换
buildLegacyFromScore(score) → {meta, scoreMeasures | staffScores}

// 2. 关系生成 (扫描 tie 标记)
buildRelations(score) → Relation[]
  // 扫描 score.parts[].measures[].voices[].entries[].tieStart
  // 找后续同 voiceId 的 tieStop
  // 生成 {type: "tie", from: id, to: id}
  // 自动设 rel.id = "r0", "r1", ...
  // 设置到 score.relations

// 3. 关系验证
validateRelations(score) → {valid: bool, errors: []}
  // - from / to entry 必须存在
  // - tie 类型: from/to 必须至少 1 个 pitch 相同
  //   (用 pitchIdentity: step+accidental+octave)

// 4. 双向同步
syncEntryFromRelation(score, rel) → bool
  // 关系 → entry 标记
  // tie: fromEntry.tieStart = true, toEntry.tieStop = true
  // slur: slurStart/slurStop
  // phrase: phraseStart/phraseStop
  // 不影响其他 type 字段
```

## 已知 B.2 限制 (接受)

1. **tie 关系无 partner** — tieStart 没找到 tieStop 不报错, 只不生成关系 (per 决策 2: 兼容残缺数据)
2. **slur / phrase 关系生成不接** — B.2 只 tie, slur/phrase syncEntryFromRelation 已实现, 但 buildRelations 不扫
3. **tuplet 关系不接** — B.3 范围
4. **tie 同 voiceId 约束** — 不允许跨 voice tie, 同 part 跨 measure OK
5. **`score.relations` 是数组** — 查找 O(n), B.4 序列化 + 索引可优化
