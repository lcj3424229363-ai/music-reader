## 4 helper API

```js
// B.2: 反向转换
buildLegacyFromScore(score) → {meta, scoreMeasures | staffScores}

// B.3 (扩): 关系生成 (types 默认全扫, [] = 空扫)
buildRelations(score, types) → Relation[]
  // tie: tieStart → tieStop
  // slur: slurStart → slurStop (允许跨 voice)
  // phrase: phraseStart → phraseStop (允许跨 voice)
  // tuplet: 按 tupletGroup 聚合 (1 group 1 Relation)

// B.3 (扩): 关系验证
validateRelations(score) → {valid, errors, warnings}
  // errors: tie 同 pitch / tuplet members count 跟 actual
  // warnings: slur 跨 voice (不 error)

// B.3 (扩): 关系 → 标记同步
syncEntryFromRelation(score, rel) → bool
  // tie/slur/phrase: from.start=true, to.stop=true
  // tuplet: 不接 (业务侧管)

// B.4: JSON 序列化
JSON.stringify(score) → 自动调 class toJSON
ScoreModel.scoreFromJSON(json) → Score
```

## P22.5-B 解决的根本问题

### 之前 (B.0 之前)
- `scoreMeasures` / `staffScores` / `documentData` 多套数据结构混用
- entry 18 修饰符字段默认值不全
- 跨 measure 关系零散在各 helper (没有统一数据模型)
- 没有 JSON 自洽序列化 (只有 documentData)
- MusicXML 跟 Score Model 完全独立

### 现在 (P22.5-B 收口)
- **统一数据契约**: Score Model 6 class 是 view/serialization
- **entry 18 + 3 tuplet 字段全默认值** (A.4 落地)
- **跨 measure 关系**: tie/slur/phrase/tuplet 4 类, 统一在 `score.relations` 顶层
- **JSON 自洽**: 5 class toJSON + scoreFromJSON, round-trip 完全一致
- **影子集成**: app.js 真的接 Score Model, 0 侵入渲染
- **app.js 业务层** (collectScoreDocument / exportScoreJson) 复用, 同时输出 Score Model JSON
