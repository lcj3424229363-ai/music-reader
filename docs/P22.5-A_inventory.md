## 2. Entry 形状 — 超重 20+ 字段

来源：`addEntryFromScoreInner` line 2027-2038 (rest) + line 2091-2107 (note)。

### 结构性（必入 Score Model）
```js
{
  kind: "note" | "rest",                // 类型
  voice: "1" | "2",                      // 谱内声部
  pitches: [{step, octave, accidental, display}],  // 仅 note，chord 时多音
  duration: "1"|"2"|"4"|"8"|"16"|"32"|"64"|"0",   // 时值码
  dotted: 0 | 1 | 2,                     // 附点
  units: 8                               // 1 quarter = 8 units (派生但实际存了)
}
```

### 时值修饰（必入）
```js
{
  tieStart: false, tieStop: false,
  slurStart: false, slurStop: false,
  fermata: false,
  tupletType: "", tupletGroup: "", tupletPosition: "",
  fullMeasure: false
}
```

### 演奏标记（每音，必入）
```js
{
  dynamic: "",       // p/mp/f/...
  pedal: "",         // "start" | "stop"
  hairpin: "",       // "cresc-start" | "decresc-start" | "stop"
  textMark: "",
  articulation: "",  // staccato/accent/tenuto/marcato
  ornament: "",      // trill/turn/mordent
  fingering: "",
  breath: false,
  grace: null|{step, octave, accidental},
  chordSymbol: ""
}
```

### UI 状态（不进 Model，进 Renderer 状态）
```js
{
  selected: false,
  placeholder: false,
  _restKey: "b/4",     // 渲染计算结果
  _ghost: false        // 预览态
}
```

**问题**：
- 结构性 / 渲染性 / UI 状态没分 — 4 类混在一个对象上
- 派生量（`units`）被存了，导致双源真相（duration 改 units 不一定跟着改）
- `_restKey` / `_ghost` 这种 transient 字段也持久化在 entry 上，序列化时容易漏清

## 4. voice 状态

```js
// line 158 hardcode
const voiceIds = ["1", "2"];

// line 359
function entryVoice(entry) {
  return String(entry.voice || "1");
}

// line 363
function entriesForVoice(entries = measureEntries, voiceId = activeVoiceId()) {
  return entries.filter((entry) => entryVoice(entry) === String(voiceId));
}
```

### 实际能力
- 2 voice（upper/lower，Sposobin 4 部写法简化）
- voice 是 entry 上的**字段**，不是单独数组
- 多 voice 不会冲突（`entriesForVoice` 过滤）
- **bug 风险**：4/4 2+2 写满时，没有强制 2 voice 各自 ≤ capacity
  - 现在用 `sumCurrentVoiceUnits()` 检查 active voice，但 other voice 写入不检查

### 缺失字段
- voice `role` (Soprano/Alto/Tenore/Basso) — MusicXML 有
- voice `name` — MusicXML 有
- voice `stem direction` — 推断，不显式

## 6. VexFlow 耦合点

### 中央工厂：`createVexNote` (line 3006-3122)

```js
function createVexNote(entry, clef, timeSignature, stemDirection, voiceId) {
  // entry 20+ 字段全部直接读
  // entry.dotted → VF.Dot
  // entry.fermata → VF.Articulation
  // entry.articulation → VF.Articulation
  // entry.ornament → VF.Ornament
  // entry.grace → VF.GraceNote + VF.GraceNoteGroup
  // entry.pedal → VF.Annotation
  // entry.fingering → VF.FretHandFinger
  // entry.textMark → VF.Annotation
  // entry.breath → VF.Annotation
  // entry.dynamic → VF.Annotation
```

**VexFlow 不直接读全局** — 全部走 `VF.*` 命名空间 (line 107: `const VF = window.VexFlow`)。

**穿透风险**：Score Model 必须兼容这 20+ 字段名 / 取值，否则 createVexNote 立刻报错。

## 7. solver 转换层

文件：`editor_to_solver.py`（P22.1 抽出来的）

### 它认的字段（输入契约）
```python
{
  "kind": "note" | "rest",
  "pitches": [{"step", "octave", "accidental"}],   # 仅 note
  "duration": "1|2|4|8|16|32|64|0",
  "dotted": 0|1|2,
  "units": <int|float>                            # 实际不用，duration 是 source of truth
}
```

**只认 6 个核心字段**。其他（voice, tie, fermata, dynamic, ...）**全部忽略**。

→ 这是未来 Score Model 的**最简化契约**：核心 6 字段稳定，其他都是渲染层关注。

## 8. MusicXML 解析现状

文件：`web/app.js` line 4730-4993

### `parseMusicXmlText` 输出
```js
{
  timeSignature: "4/4",
  keySignature: "C",
  staves: {
    treble: [entries[], entries[], ...],   // 每 measure 一个数组
    bass:   [entries[], entries[], ...]
  }
}
```

**重要：解析结果直接铺成 `Entry[]` 数组** — 和我们自己的存储格式**完全相同**。

### 解析时认的字段
- 音高：`pitches: [{step, octave, accidental}]`
- 时值：`duration`, `units`（从 divisions 算）
- 装饰：`dynamic`, `pedal`, `hairpin`, `textMark`, `chordSymbol`, `grace`
- 多音：`note.chord` → 叠加到上一 entry 的 `pitches`
- 多声部：`<backup>` 跨 voice，用 `voiceLists[voiceId] = []` 分组

### 解析时**忽略的字段**
- `articulation` — 没解析
- `ornament` — 没解析
- `fingering` — 没解析
- `breath` — 没解析
- `tie` (跨 measure) — 没解析
- `tuplet` — 没解析
- `fermata` — 没解析

→ MusicXML → Score Model → 渲染 的转换层目前**不完整**，要补。

## 9. 编辑历史 (line 3757-3823)

```js
function snapshotEditor() {
  return {
    entries: JSON.parse(JSON.stringify(measureEntries)),  // 深拷贝当前小节
    selectedEntryIndex,
    measureIndex: currentMeasureIndex
  };
}

function commitEdit(callback) {
  editHistory.push(snapshotEditor());
  if (editHistory.length > 80) editHistory.shift();
  try {
    callback();
    repairTupletGroups();
    normalizeSelection();
    renderNotation();
  } catch (error) {
    handleRenderError(error);
  }
}
```

### bug / 限制
- **只 snapshot 当前小节** — 跨小节编辑后 undo 不可逆
- **跨 staff 切换不 snapshot** — 切到 bass 改完再切回 treble undo，会回到当前 bass 状态（错的）
- max 80 步
- 深拷贝用 `JSON.parse(JSON.stringify())` — 慢，丢失 `undefined` / 函数 / Date

## 10. 缺失的概念（未来 Score Model 要补）

按用户的核心论断"5 大功能堆在 app.js 上"反推：

| 概念 | 现状 | 缺失 | Score Model 要补 |
|------|------|------|-----------------|
| Part (乐器) | 没有 | hardcode treble/bass | `parts[]` 数组 |
| 多 staff per part | 没有 | treble/bass 散列 | `parts[i].staves[]` |
| Instrument | 没有 | 整个抽象缺失 | `part.instrument: {name, midiProgram, ...}` |
| Voice role | 没有 | Sposobin 4 部标注缺失 | `voice.role: "S"|"A"|"T"|"B"` |
| Key changes | 输入框存在 | 未接入数据 | `measure.keySignature: "C"` |
| Time sig changes | UI 没有 | 数据没有 | `measure.timeSignature: "3/4"` |
| Anacrusis | 字段有 | 未接入数据 | `score.anacrusis: true` |
| Cross-measure tie | entry.tieStart | 跨 measure 不验证 | `tie: {startMeasure, startIndex, endMeasure, endIndex}` |
| Cross-measure slur | entry.slurStart | 跨 measure 不验证 | `slur: {...}` 同 tie |
| Tuplet span | entry.tupletGroup | 跨 measure 不验证 | `tuplet: {startRef, endRef, ratio}` |
| Tempo per measure | tempoInput | 数据没有 | `measure.tempo: 120` |
| 跨小节 direction | attach 到当前 measure | 不跨 measure | `measure.directions: [...]` |

## 11. P22.5-B 设计输入约束（从摸底里提取）

### 必须稳定的字段（兼容性）
1. **结构性 6 字段**：`kind`, `voice`, `pitches`, `duration`, `dotted`, `units`
   - solver 转换层依赖
   - MusicXML 解析产物
   - createVexNote 读

2. **时值修饰 8 字段**：`tieStart`, `tieStop`, `slurStart`, `slurStop`, `fermata`, `tupletType`, `tupletGroup`, `tupletPosition`, `fullMeasure`

3. **演奏标记 10 字段**：`dynamic`, `pedal`, `hairpin`, `textMark`, `articulation`, `ornament`, `fingering`, `breath`, `grace`, `chordSymbol`

### 必须分层的概念
```
Score
├── meta: {title, composer, tempo, anacrusis}
├── parts: [Part, ...]
│   ├── id, name, instrument
│   └── staves: [Staff, ...]
│       ├── clef, keySignature
│       └── voices: [Voice, ...]
│           └── id, role
└── measures: [Measure, ...]      ← or 分散在每个 staff/voice 上?
    ├── number, timeSignature
    ├── beginBarline, endBarline
    ├── directions: [...]
    └── events: [Event, ...]      ← note | rest | chord
```

### 关键设计决策（待 P22.5-B 拍板）
- **measure 粒度**：per part / per staff / per voice？
- **跨 measure 关系**：tie/slur/tuplet 用 reference (id) 还是嵌套？
- **节奏单位**：保留 `units`（1 quarter = 8）还是改 `Fraction`？
- **与 P22.3 editorState 的关系**：editorState 是输入态，Score Model 是文档态 — 二者并存
- **与 VexFlow 边界**：Score Model 不导 VF.*；Renderer 是唯一允许的 VF 使用方

## 12. 摸底结论 — 风险点

1. **20+ 字段 entry 不会自然消解** — 必须显式分类（结构 / 修饰 / 演奏 / 状态）
2. **Part 抽象完全缺失** — 大谱表现在是 hardcode `staffScores` 字典，不是数组
3. **跨小节关系没人接** — tie/slur/tuplet 都标在 entry 上但没验证跨 measure
4. **VexFlow 工厂是事实边界** — `createVexNote` 决定 Score Model 必须有哪 20 字段
5. **solver 转换只认 6 字段** — 这是最小契约，Score Model 改动不能破坏
6. **MusicXML 解析不完整** — articulation/ornament/fingering 等不解析，导入会丢
7. **editHistory 只 snapshot 当前小节** — undo 不完整（不阻塞 P22.5 但要记住）
8. **`units` 双源真相** — 派生字段被存了，duration 改了 units 不一定改
