## TL;DR

**B.5 关键发现**: app.js **目前完全不用 Score Model** (grep 0 匹配)。CoordinateSystem (`cs`) 已经是全局单例,在 render 末尾用 `cs.updateLayout({staffGeometry, trebleGeometry, bassGeometry, measureRects, currentMeasureIndex, timeSignature})` 接 3 套 geometry。

Score Model 数据层不 import VexFlow (B.1 决策 5B 半隔离),所以 B.5 收口思路是 **影子模式 0 侵入**:
- app.js 业务层在 render 末尾 build 一次 Score,验证 buildScore 在生产数据上工作
- collectScoreDocument 改走 Score Model 路径(可选)
- 渲染主循环 (`drawStaffEntriesOnStave`) 不动 — 风险太大
- 关系(Relations)仍是序列化概念,渲染看 entry 标记 (A.3 现状)

### 1.4 `collectScoreDocument` (L4409) 现状

```js
function collectScoreDocument() {
  // ... return {schemaVersion, title, timeSignature, keySignature, tempo, anacrusis,
  //              staffMode, voiceRoleMap, activeStaff, activeVoice, measureCount,
  //              staves: [{id, staffNumber, label, clef, measures: [{number, beginBarline, endBarline, voices: [{id, role, usedUnits, entries}]}]}]}

```

返回的是 **legacy `documentData`**,跟 Score Model 形状接近但不一致:
- documentData 顶层有 schemaVersion / timeSignature / keySignature / tempo / staffMode / voiceRoleMap / activeStaff / activeVoice (Score Model 没有)
- documentData.staves[].measures[].voices[].entries (legacy 命名,不是 `notes`)

B.5 思路: **`collectScoreDocument` 仍然返回 legacy**(避免大改),但 exportScoreJson 路径加一步 buildScore 做 invariant check。

## 3. 实施范围 (按推荐决策)

### 3.1 影子验证 (renderNotation 末尾 + exportScoreJson)

**3.1.1 renderNotation 末尾加 buildScore side-effect** (0 侵入, 1 行)
```js
// P22.5-B.5: 影子验证 — buildScore 在生产数据上工作, 关系生成 + 验证
if (typeof window.ScoreModel !== "undefined" && window.ScoreModel.buildScore) {
  try {
    const isPiano = staffMode?.value === "piano";
    const legacy = isPiano
      ? {staffScores: {treble: {measures: trebleState?.measures || []}, bass: {measures: bassState?.measures || []}}}
      : {scoreMeasures: activeStaffState?.measures || []};
    const shadowScore = window.ScoreModel.buildScore(legacy);
    window.ScoreModel.buildRelations(shadowScore);
    const v = window.ScoreModel.validateRelations(shadowScore);
    if (!v.valid) {
      // 影子层不抛错, 只 console.warn — 不能破渲染
      console.warn("[P22.5-B.5 shadow] validateRelations found:", v.errors, v.warnings);
    }
  } catch (e) {
    console.warn("[P22.5-B.5 shadow] buildScore failed:", e);
  }
}
```

**3.1.2 exportScoreJson 路径加 buildScore 输出**
- 当前: `scoreDataOutput.value = JSON.stringify({score: documentData, validation}, null, 2);`
- B.5 改: 同时输出 `{score: documentData, scoreModel: JSON.parse(JSON.stringify(score)), validation}`

### 3.2 关系生成 (buildRelations) 在 shadow 路径
