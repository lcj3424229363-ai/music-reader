## TL;DR

P22.5-B.1 落地 Score Model **数据契约层**:
- 6 个 ES6 class (Score, Part, Measure, Voice, Entry, Relation) — 全部用 class 语法, 简洁可序列化
- 1 个 factory `buildScore(legacyState)` — 把老 `scoreMeasures` / `staffScores` 转换成 Score Model
- 影子模式 (决策 4): 老 `scoreMeasures` 仍真数据, Score Model 是 view/serialization
- 半隔离 (决策 5): 数据层不引用 VexFlow, 字段名沿用 VexFlow 习惯

**5 决策落地** (用户拍板 1A 2A 3A 4B 5B):
1. **A per voice** — `Measure.voices[]` 数组, 1 measure 跨声部对齐
2. **A reference (id)** — `Relation{type, from, to}` 独立关系对象
3. **A 保留 units** — 1 quarter = 8, 老字段不动
4. **B 影子** — `scoreMeasures` 仍真数据, Score Model 是 view
5. **B 半隔离** — 数据层不 import VexFlow, Renderer 翻译留给 P22.6

## 6 class 概览 (B.1 范围)

```js
class Entry    { id, kind, voice, pitches[], duration, dotted, units,
                 articulation, fingering, textMark, ornament, fermata,
                 grace, dynamic, pedal, breath,
                 tieStart, tieStop, slurStart, slurStop,
                 phraseStart, phraseStop, hairpin,
                 chordSymbol, arpeggiate, volta, rehearsalMark }
class Voice    { id, role, entries[] }
class Measure  { index, number, timeSignature, beginBarline, endBarline,
                 voices[], tempo, directions[], volta, rehearsalMark }
class Part     { id, name, instrument, staves[], measures[] }
class Relation { id, type, from, to, payload{} }
class Score    { meta{title, composer, tempo, anacrusis}, parts[], relations[],
                 addPart, getPart, getMeasure, addRelation, getRelationsByType }
```

## 已知 B.1 限制 (接受)

1. **影子模式**: `scoreMeasures` 仍是真数据, Score Model 是 view。app.js 渲染循环没切到 Score Model (B.5 范围)
2. **relation 暂未生成**: factory 只搬 entry 字段, tie/slur/tuplet 关系对象没建 (B.3 范围)
3. **序列化没做**: 没 toJSON / fromJSON, 也没 MusicXML 双向 (B.4 范围)
4. **per voice 决策已落地**: factory 按 legacy entry 的 `voice` 字段分到 `Measure.voices[]`, 但 `scoreMeasures[i]` 是 flat 数组, 实际"多 voice"得 caller 传 `voice: "1" / "2"` 才生效
5. **barline / tempo 还在 legacy settings**: `Measure.beginBarline / endBarline` 从 `staffState.settings[i]` 取, 单谱表 fallback 默认 "single"
