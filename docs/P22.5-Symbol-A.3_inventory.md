## TL;DR

A.3 修复"跨 measure 的 tie/slur/hairpin 找不到 target、画不出来"。**根因**: 6 个查询函数 + 3 个绘制函数全部基于 `notationEntries` (单 measure 局部数组), 跨 measure 时 `for` 循环跑完找不到。

**A.3 三大块**:
1. **数据层** — 新增 `buildScoreEntries()` 全局 flatten 索引
2. **查询层** — 6 个 `next*/previous*` 函数改接受全局
3. **绘制层** — 3 个 `draw*` 函数改接受全局, 跨 measure 走 raw SVG path (VexFlow 限制)

**A.3 不动**:
- 4 部画布调用 (`renderFourPartScore` L1534) — 留给 A.4
- `tieIndexes` (L3500) — utility 局部, 接受任何两个 entry, 不需改
- 数据结构 (`entry.tieStart/tieStop/slurStart/slurStop/hairpin`) — 已经是单 entry 上的 flag, 不动

## 2. 实施计划 (A+A+B)

### 2.1 数据层 — 新增 `buildScoreEntries()`

放在 `pickAnnotationOrder` 附近 (L3006 之后)。

```js
// P22.5-Symbol-A.3 — 全局 flatten 索引
// 在每次 render 前调用, 跨 measure 查找用
// 每个 entry 上挂 3 个 _ 前缀字段: _globalIndex / _measureIndex / _localIndex
function buildScoreEntries(scoreMeasures) {
  const all = [];
  scoreMeasures.forEach((measure, measureIndex) => {
    const entries = measure?.notationEntries || measure?.entries || [];
    entries.forEach((entry, localIndex) => {
      all.push({
        ...entry,
        _globalIndex: all.length,
        _measureIndex: measureIndex,
        _localIndex: localIndex,
      });
    });
  });
  return all;
}
```

**挂载点**: `state.scoreEntries = buildScoreEntries(scoreMeasures)` (在 renderCurrentMeasure 主循环前)

**销毁**: render 后保留引用 (供业务层 toggleSelectedFlag 跨 measure 用)

### 2.2 查询层 — 6 个函数改签名

| 函数 | 新签名 | 改法 |
|------|--------|------|
| `nextTieTargetIndex` | `(scoreEntries, startIndex, skipPlaceholder=true)` | 循环范围 `scoreEntries` 全局, 返回 globalIndex |
| `previousTieSourceIndex` | 同上 | 反向 |
| `nextTieTargetEntry` | `(scoreEntries, startIndex)` | 改成 `(scoreEntries, startIndex)` 返回 entry, 业务层 L3975 调用点改 |
| `nextSlurTargetIndex` | 同 nextTieTargetIndex | 同 |
| `nextSlurTargetEntry` | 同 nextTieTargetEntry | 同 |
| `previousSlurSourceIndex` | 同 previousTieSourceIndex | 同 |
| `nextHairpinStopIndex` | 同上 | 同 |

**backward-compat 安全**: 老函数保留为内部 wrapper (调新函数 + `notationEntries` 作为 scoreEntries 子集传入), 避免破坏其他调用点。

但**实际**: A.3 之前 `notationEntries` 是 measure 内数组, A.3 之后全局 scoreEntries 包含所有 measure. 如果保留老 wrapper 接受 `notationEntries` 单 measure, 行为会"局部查"。

**简化决策**: 6 个函数签名直接换, **不保留老 wrapper**。3 个绘制函数 + 2 个业务调用点同步改。

### 2.3 绘制层 — 3 个函数改

```js
// 新签名: 接受全局 scoreEntries + allNotes (按 globalIndex 排)
function drawEntryTies(context, scoreEntries, allNotes) { ... }
function drawEntrySlurs(context, scoreEntries, allNotes) { ... }
function drawEntryHairpins(context, scoreEntries, allNotes, staves) { ... }  // staves per measure
```

**`allNotes` 构建**: 在 render 时一次性构建, 按 `globalIndex` 索引:
```js
const allNotes = scoreEntries.map(entry => /* 从对应 measure 的 item.notes 取 */);
```

**跨 measure 几何 (B 选项 — raw SVG path)**:
- **同 measure**: 走 VexFlow `VF.StaveTie` / `VF.Curve` / `drawHairpinWedge` (不变)
- **跨 measure**: VexFlow 的 `VF.StaveTie` / `VF.Curve` 跨 system 行为未定义 (A.2 经验: VexFlow 限制), 走 raw SVG path 手动画
  - tie: 画两点间二次贝塞尔曲线 (上弧/下弧, 根据 voiceId 决定)
  - slur: 同 tie 但更弯 (cps 高度 18 → 28)
  - hairpin: 跨 measure 用 raw `context.beginPath/moveTo/lineTo/stroke`

**新 helper**:
```js
function drawCrossMeasureTie(context, note1, note2, indexes, direction) {
  // direction: "up" | "down"
  // 用 note1.getTieRightX() + note2.getTieLeftX() + 各自 y 画贝塞尔
}
function drawCrossMeasureSlur(context, note1, note2) { /* 同上 */ }
function drawCrossMeasureHairpin(context, hairpin, note1, note2, y, spread) { /* 同上 */ }
```

### 2.4 调用点改造

**L2918-2921 单 measure 渲染循环**:
```js
// 旧:
drawEntryTies(context, item.notationEntries, item.notes);
drawEntrySlurs(context, item.notationEntries, item.notes);
drawEntryHairpins(context, item.notationEntries, item.notes, stave);

// 新 (在循环外 build 一次):
//   state.scoreEntries = buildScoreEntries(scoreMeasures);
//   allNotes = ...
//   staves = ...
// 循环内 (按 measure 调):
drawEntryTiesForMeasure(context, measureIndex, scoreEntries, allNotes, staves);
drawEntrySlursForMeasure(context, measureIndex, scoreEntries, allNotes, staves);
drawEntryHairpinsForMeasure(context, measureIndex, scoreEntries, allNotes, staves);
```

或者更简单: **循环外一次性全画**, 不分 measure:
```js
drawEntryTies(context, scoreEntries, allNotes);  // 跨 measure 自动走 fallback
drawEntrySlurs(context, scoreEntries, allNotes);
drawEntryHairpins(context, scoreEntries, allNotes, staves);
```

**决策**: 走"循环外一次"更简单, 但需要 `staves` 是 array 索引 per measure。

### 2.5 业务层

**L3975 / L3980** 改:
```js
// 旧:
const target = nextTieTargetEntry(selectedEntryIndex);
const target = nextSlurTargetEntry(selectedEntryIndex);

// 新:
const target = nextTieTargetEntry(state.scoreEntries, selectedEntryIndex);
const target = nextSlurTargetEntry(state.scoreEntries, selectedEntryIndex);
```

**`selectedEntryIndex` 是全局还是局部?**: 当前是单 measure 局部 (`selectedEntryIndex` 在 `measureEntries` 数组里)。需要**先确认** `selectedEntryIndex` 的 scope — 如果是 measure 局部, A.3 改成全局需要重写 selectedEntryIndex 的语义。

⚠️ **重要调研点**: `selectedEntryIndex` 的赋值/读取点 (grep `selectedEntryIndex`) — 摸底时只看了 L3975/3980, 没看完整 scope。这是 A.3 实施的 blocker 之一。

## 4. 风险点 (实施必知)

| 风险 | 影响 | 缓解 |
|------|------|------|
| VexFlow 跨 system tie/slur 行为未定义 | A.3 走 fallback raw SVG path |
| 跨 measure hairpin y 坐标 (stave.getYForLine) | 用两个 measure 的 stave 各取一次 y |
| `selectedEntryIndex` scope 模糊 | 先 grep 全文, 必要时同步改 |
| `tieIndexes` 跨 measure 时 (note 数不同) | 仍按局部匹配, 可能空 indexes, 容错 |
| raw SVG path 视觉跟 VexFlow 不一致 | 用相同颜色 + 相同 thickness, 视觉接近 |
| 循环外 build `allNotes` 增加内存 | scoreEntries 上限 ~1000 notes, 内存可忽略 |
