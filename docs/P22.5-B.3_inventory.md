# P22.5-B.3 摸底 — 跨 measure 关系 (slur / phrase / tuplet)

**日期**: 2026-08-14
**状态**: 📋 摸底 + 决策点 + 推荐,等用户拍板
**前置**: P22.5-B.1 ✅ (6 class + factory) + P22.5-B.2 ✅ (4 helper)

## TL;DR

P22.5-B.3 要落地 3 个关系类型:
1. **slur 关系** — 跟 tie 形态一致 (from-to), 但业务可跨 voice
2. **phrase 关系** — 跟 slur 几乎一样, MusicXML 用 number=2 区分
3. **tuplet 关系** — 形态不同, 1 group = N entry, 需新决策

**B.3 必修** (发现新根因):
- ❗ **B.1 `legacyEntryToEntry` 漏了 tuplet 3 字段** (tupletType/tupletGroup/tupletPosition)
- ❗ **Entry class 没这 3 字段** (它们在 18 修饰符之外)
- ❗ **老 code path** (app.js L1009-1724) 一直用 3 字段工作, 但 Score Model 完全丢

## 1. 摸底结果

### 1.1 slur/phrase 跟 tie 同形态 (B.3 主要复用 B.2)

```
tie:    entry.tieStart: true   + entry.tieStop: true   (validate: 同音高)
slur:   entry.slurStart: true  + entry.slurStop: true  (validate: 业务可跨 voice)
phrase: entry.phraseStart:true + entry.phraseStop: true (MusicXML number=2)
```

**A.3 跨 measure 已有**:
- ✅ `drawEntrySlurs` / `drawEntryPhraseMarks` / `drawEntryTies` (L3503+)
- ✅ 跨 measure 走 raw SVG path: `drawCrossMeasureSlur` / `drawCrossMeasurePhraseMark` / `drawCrossMeasureTie`
- ✅ 同 measure 走 VexFlow: `VF.Curve` / `VF.StaveTie`

**业务层**:
- `toggleSelectedFlag("slurStart" / "slurStop" / "phraseStart" / "phraseStop")` (L4281+)
- slur/phrase start 设了会取消 stop (互斥)

### 1.2 tuplet 形态不同 (B.3 核心新决策)

**当前 3 字段** (在 legacy entry, 不在 18 修饰符):
```js
entry.tupletType     // "" | "triplet" | "quintuplet" | "sextuplet"
entry.tupletGroup    // string (groupId, 自生成: "tuplet-<timestamp>-<index>")
entry.tupletPosition // "" | "start" | "middle" | "end"
```

**业务约束** (L4105+):
- `repairTupletGroups`: 启动时验证 group (count 跟 ratio 一致, position 顺序对, 都在同 voice 连续)
- `toggleTupletGroup`: 1 选 start, 自动给后续 N-1 个 entry 设 middle/end
- `createEntryTuplets`: 扫 `tupletPosition === "start"`, 取 `notationEntries.slice(index, index + totalNotes)` 同 measure

**tuplet 跟 tie 区别**:
| 维度 | tie | tuplet |
|------|-----|--------|
| 字段形态 | start + stop (2 entry) | groupId 串接 (N entry) |
| 跨 measure | 支持 (B.2 已做) | **不支持** (业务只单 measure) |
| 跨 voice | 不允许 (B.2 决策) | 不允许 (同 voice 连续) |
| 跨 entry 数 | 固定 1→1 | 3/5/6 个 (跟 type) |
| 渲染触发 | start 触发 | start 触发 |

### 1.3 B.1 落地时的疏漏

`legacyEntryToEntry` (L232-257) 只拷 18 修饰符, **完全没拷 tuplet 3 字段**:

```js
const fields = [
  "articulation", "fingering", "textMark", "ornament", "fermata",
  "grace", "dynamic", "pedal", "breath",
  "tieStart", "tieStop", "slurStart", "slurStop",
  "phraseStart", "phraseStop", "hairpin",
  "chordSymbol", "arpeggiate", "volta", "rehearsalMark"
  // 缺: "tupletType", "tupletGroup", "tupletPosition"
];
```

**后果**: 用 buildScore 转 legacy → Score, tuplet 字段全丢 → 渲染会丢 tuplet

**B.3 必修**:
1. Entry class constructor 加这 3 字段默认值
2. `legacyEntryToEntry` fields 数组补这 3 个
3. `entryToLegacyEntry` 已经是 for-in 拷全部, 不用改

## 2. 9 决策点 (待拍板)

| # | 决策点 | 选项 | 推荐 | 理由 |
|---|--------|------|------|------|
| 1 | **Entry tuplet 字段归属** | (a) 加到 18 修饰符 → ENTRY_MODIFIER_DEFAULTS 也加 (b) Entry 加独立 3 字段 (c) 维持 B.1 现状 (丢字段) | **(b) Entry 独立 3 字段** | tuplet 不是单 entry 属性, 是 group 协同; 跟 A.4 ENTRY_MODIFIER_DEFAULTS 语义不同 (后者是 "entry 自身默认") |
| 2 | **slur / phrase 关系模型** | (a) from-to (跟 tie 同) (b) entryIds[] group (c) 不归关系 | **(a) from-to** | 跟 MusicXML `<slur>` 形态对齐, 跟 tie 同结构, 复用 buildRelations 路径 |
| 3 | **tuplet 关系模型** | (a) from-to start→end (b) entryIds[] group + payload.ratio (c) 不归关系 (业务侧管) | **(b) entryIds[] + payload** | tuplet 业务上是 N entry group, from-to 丢中间 entry; payload.ratio 存 "3:2" 等 |
| 4 | **slur 跨 voice** | (a) 允许 (跟业务匹配) (b) 不允许 (跟 tie 严格) | **(a) 允许** | 实际乐谱上→下连音常见; 业务 UI 也允许 |
| 5 | **phrase 跨 voice** | (a) 允许 (b) 不允许 | **(a) 允许** | 跟 slur 同, MusicXML phrase 也跨 voice |
| 6 | **tuplet 跨 measure** | (a) 支持 (b) 不支持 (B.3 范围) | **(b) 不支持** | 当前 `createEntryTuplets` / `repairTupletGroups` 都不支持, 跨 measure 罕见 |
| 7 | **buildRelations 签名** | (a) `buildRelations(score, types)` 通用 (b) `buildTieRelations / buildSlurRelations / ...` 4 个 | **(a) 通用** | 1 个函数内部按 types 过滤, 复用 entryIndex; 简单 |
| 8 | **validateRelations 规则** | (a) tie 同 pitch + slur/phrase 不校验音高 + tuplet group count 跟 ratio 一致 (b) slur/phrase 也校验同音高 (c) tuplet 不校验 | **(a)** | 跟业务匹配: tie 是同音延音, slur/phrase 是不同音连线 |
| 9 | **syncEntryFromRelation 扩展** | (a) 加 slur/phrase 分支, tuplet 不接 (b) 只 tie 分支 | **(a) slur/phrase 加分支, tuplet 不接** | slur/phrase 跟 tie 同样 from-to 简单; tuplet 是 group, sync 复杂且容易循环, 业务侧管 |

## 3. 实施范围 (按推荐决策)

### 3.1 Entry class 扩展 (3 字段)
- 加 `tupletType / tupletGroup / tupletPosition` (3 字段, 3 默认值: "" / "" / "")
- 默认值: `tupletType: ""`, `tupletGroup: ""`, `tupletPosition: ""`

### 3.2 `legacyEntryToEntry` 字段补全
- fields 数组加这 3 个

### 3.3 `buildRelations` 扩展
```js
function buildRelations(score, types = ["tie", "slur", "phrase", "tuplet"])
  // 扫 entry 上对应标记, 生成 Relation 对象
  // tie: tieStart → tieStop
  // slur: slurStart → slurStop
  // phrase: phraseStart → phraseStop
  // tuplet: 按 tupletGroup 聚合 → 1 个 Relation (payload.ratio + payload.entryIds)
```

### 3.4 `validateRelations` 扩展
- tie: 同音高 (B.2 有)
- slur: 不校验音高 (新)
- phrase: 不校验音高 (新)
- tuplet: group entryIds.length 跟 payload.ratio 一致 (新)

### 3.5 `syncEntryFromRelation` 扩展
- tie: 已有
- slur: slurStart/slurStop 分支 (新)
- phrase: phraseStart/phraseStop 分支 (新)
- tuplet: 不接 (避免循环)

### 3.6 测试 (估 18-20 测试, 6-7 class)
- TestBuildRelations 扩展: slur same/cross measure / phrase / tuplet single / tuplet 跨 voice 不生
- TestValidateRelations 扩展: slur 不校验音高 / tuplet group count 错
- TestSyncEntryFromRelation 扩展: slur / phrase 分支
- TestTupletGroup 新: 3 entry triplet / 5 entry quintuplet / 跨 voice 不聚
- TestEntryTupletFields 新: Entry 3 字段默认值 / legacyEntryToEntry 拷贝
