## TL;DR

   - **ABOVE** (从近到远): articulation → fingering → textMark → ornament → fermata
   - **独立**: grace (不变位置)
   - **BELOW** (从近到远): dynamic → pedal → breath

3. **chordSymbol 改 `setHorizontal(LEFT=0) + setVertical(BOTTOM=1)`** (L3125-3131) — 从 `CENTER_STEM=4 + TOP=1` 错开 ABOVE/BELOW stack。

## VexFlow 4.x 死 API 验证（重要 — A.3/A.4 不要再走 setYShift 路径）

实施前先 grep 了 VexFlow 4.x `setYShift / setXShift / yOffset / xOffset`：

| API | 状态 |
|-----|------|
| `Element.setYShift` setter | 存在 (基类) |
| `Element.setXShift` setter | 存在 (基类) |
| `Element.yShift` 字段 init | `0` (构造时) |
| `Element.xShift` 字段 init | `0` (构造时) |
| `Element.yOffset` 字段 init | `0` (构造时) |
| `Element.xOffset` 字段 init | `0` (构造时) |
| **渲染管线读这些字段的代码** | **0 hit** |

**结论**: 字段 init=0 但**全 vexflow.js 1.1MB 无任何渲染代码读这些字段**。VexFlow 4.x 走 Canvas 2D `context2D.translate(x, y)`, modifier y 位置**没有 public API override**。setYShift 是死 API。

**回退方案**: 用 VexFlow addModifier 顺序自动 stack — 第一个 add 的在最里层(最近 note), 后面的依次外推。这是 VexFlow 4.x 唯一可控的 modifier 排版方式。

## 已知 A.2 限制（接受）

1. **5 ABOVE 同时存在时 VexFlow 自动 stack 间距固定** (~8px) — 极端情况下可能撞 staff 上沿。这是 VexFlow 4.x 限制, 接受。
2. **chordSymbol 实际位置**: LEFT+BOTTOM = 文本框锚点左下角对齐 note head, 但 VexFlow 内部仍会把 chordSymbol 当 ABOVE 处理 (在它自己 stack 里)。如果想让 chordSymbol 真在 stem 下面, 需要 post-render transform (VexFlow 4.x 限制, 接受)。
3. **`pickAnnotationOrder` 暂未被 `createVexNote` 直接调用** — 10 个 if 块顺序是手动排的, helper 仅作为"参考实现 + 文档 + 测试 oracle"。这是有意为之: helper 用 `entry` 抽象, 但 createVexNote 还需要每个 slot 的 VexFlow 特定构造参数, 直接调用反而要传很多 boilerplate。
