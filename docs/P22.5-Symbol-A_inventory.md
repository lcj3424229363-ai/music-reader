## 4. 用户说"谱面不展示" — 12 个潜在根因

既然 **17 类符号的 UI / entry / renderer 全都有**，问题不出在"缺失"，**出在**：

### 根因 #1 — `addTickables` 抛错时整 voice 静默失败 ⚠️⚠️
**位置**：`drawStaffEntriesOnStave` line 2892-2902
```js
try {
  voice.addTickables(notes);
} catch (e) {
  console.error("[addTickables] voice %s failed: %s ...");
  return;  // ← 整个 voice 静默 return, 但 allTuplets/allBeams 已被 push
}
```
**症状**：voice 1 添加失败 → return → 后续 `voice.draw()` 不调 → 整谱面没音符
**触发条件**：`voice.addTickables` 失败 (e.g. duration 不合法 / pitches 数超 4)
**展示症状**：整谱白板，**用户感觉"啥都没了"** — 可能被误解为"符号没展示"

### 根因 #2 — 多个 `VF.Annotation` 同 position 叠加 ⚠️
**位置**：`createVexNote` line 3073-3102
- `textMark` → position `ABOVE` (line 3074)
- `pedal` → position `BELOW` (line 3060)
- `breath` → position `BELOW` (line 3085)
- `dynamic` → position `BELOW` (line 3093)

**症状**：dynamic + pedal + breath 同时打开 → 3 个 annotation 全在 BELOW → **互相覆盖**
**触发条件**：用户给同一音符加 dynamic + pedal
**展示症状**：只看到最下面那个（dynamic），其他被覆盖

### 根因 #3 — `chordSymbol` 用了 CENTER_STEM 但没有 stem 调整 ⚠️
**位置**：`createVexNote` line 3103-3111
```js
.setHorizontal(VF.ChordSymbol?.HorizontalJustify?.CENTER_STEM ?? 4)
.setVertical(VF.ChordSymbol?.VerticalJustify?.TOP ?? 1)
```
**症状**：TOP + CENTER_STEM → 浮在 staff 上方但被 stem 干扰
**展示症状**：和弦标记看不清 / 与其他 annotation 撞

### 根因 #4 — selectedEntryIndex === -1 时 UI 静默 return ⚠️⚠️
**位置**：`toggleSelectedFlag` line 3943-3945, `setSelectedDynamic` line 3988-3990
```js
const entry = measureEntries[selectedEntryIndex];
if (!entry) return;
```
**症状**：用户**没先点选音符**就改 UI → 控件值变了但 entry 没写 → 用户感觉"选了但没生效"
**触发条件**：第一次点 ribbon 控件但还没点过任何音符
**展示症状**：UI 显示"已选"但谱面不变

### 根因 #5 — bridge 同步发 change event 但 select 无对应 option ⚠️
**位置**：`syncRibbonToTarget` line 5495-5497
```js
target.value = src.value;
target.dispatchEvent(new Event("change", { bubbles: true }));
```
**症状**：ribbon 控件 value 不在 target option 列表里 → `target.value` 静默失败 → change 事件触发但 entry 写的是空字符串
**触发条件**：P18.8 重构时 ribbon 命名空间和 inspector 命名空间不一致
**展示症状**：选了"staccato"但 entry.articulation = ""

### 根因 #6 — `drawEntryTies` 跨小节不工作 ⚠️
**位置**：`nextTieTargetIndex` line 3459-3466 — **只在当前 measureEntries 数组内找**
```js
for (let index = startIndex + 1; index < notationEntries.length; index += 1) {
  ...
  if (!entry.placeholder && entry.kind === "note") return index;
  if (!entry.placeholder && entry.kind === "rest") return -1;  // ← 跨小节不画
}
```
**症状**：tieStart 在小节 1 末尾，tieStop 在小节 2 开头 → 找不到 target → 不画
**触发条件**：tie 跨小节线
**展示症状**：tie 字段已设但谱面没线

### 根因 #7 — 4 部画布 (`renderFourPart`) 不走 `createVexNote` ⚠️
**位置**：`renderFourPart` line 1553-1583
```js
const voice = new VF.Voice({ numBeats: meter.numerator, beatValue: meter.denominator });
voice.setMode(VF.Voice.Mode.SOFT);
VF.Accidental.applyAccidentals([voice], "C");
const beams = VF.Beam.generateBeams(notes, {...});
```
**症状**：4 部写完显示的 4-part canvas **没有修饰符号**（没走 createVexNote）
**触发条件**：用户点 4 部写作按钮
**展示症状**：4 部只有音符，没有 articulation / dynamic / 等 — 这是设计差异不是 bug，但用户可能误以为是 bug

### 根因 #8 — ghost note 不带符号 ⚠️
**位置**：`createVexNote` line 3039-3111
- 所有 `if (entry.kind === "note" && entry.X && VF.Y)` 分支都读 entry 字段
- **但** ghost entry 只有 `{kind, voice, pitches, duration, dotted, units, _ghost:true}` (line 222)
- 永远不会有 articulation / dynamic 等字段

**症状**：ghost preview 永远是"裸音符"，没符号 — 这是设计（ghost 是预览位置）
**展示症状**：用户可能感觉"我选了 articulation 但谱面没反应" — 实际是 ghost 没符号是正常的，但**点 commit 后真音符应该有**

### 根因 #9 — articulation 位置跟 stem 方向冲突
**位置**：`createVexNote` line 3044
```js
const artPosition = voiceId === "2" ? (VF.Modifier?.Position?.ABOVE ?? 3) : (VF.Modifier?.Position?.BELOW ?? 4);
```
**症状**：voice 1 stem 向上 → articulation 在 BELOW；voice 2 stem 向下 → articulation 在 ABOVE
**问题**：staccato 默认在 stem 同一侧是惯例，**但**如果 stem 因 voice 选择冲突会跑到错误侧
**触发条件**：voice 1 + 短音符（八分/十六分）staccato 应该在 stem 同侧

### 根因 #10 — 多 note (chord) 时 single position 不分
**位置**：`createVexNote` line 3010-3012
```js
const keys = isRest ? [restKey] : entry.pitches.map(...);
```
**症状**：chord (多 pitches) 时所有音符共享一个 articulation position → 上层音可能被 articulation 盖住
**触发条件**：用户加 chord 然后选 articulation

### 根因 #11 — renderFourPart 与编辑谱面不同步
**位置**：line 1553
- 编辑器谱面走 `createVexNote`
- 4 部 canvas 走 `new VF.StaveNote` 直接造

**症状**：4 部 canvas 不响应编辑器编辑（这是设计：4 部是 solver 输出的独立画布）
**展示症状**：用户可能混淆"4 部画布没符号"和"编辑器没符号"

### 根因 #12 — `fermata` 用了通用 "a@a" 不是真正的 fermata
**位置**：`createVexNote` line 3041
```js
note.addModifier(new VF.Articulation("a@a").setPosition(abovePosition), 0);
```
**症状**：VexFlow 4.x 的 "a@a" 是 generic 长停顿符，**不一定是 fermata** (fermata 通常是 "a@fermata" 或 "fermataAbove")
**触发条件**：用户按 fermata 按钮
**展示症状**：显示一个 "𝄐" 通用停顿符而不是标准 fermata "𝄐"
